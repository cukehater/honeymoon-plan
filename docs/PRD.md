# 허니문 플래너 PRD

2026-11-07 기준. 원본은 Claude Docs의 "허니문 플래너 PRD" 문서다.

## 개요와 목표

포르투·바르셀로나 신혼여행(2026.11.30~12.08) 일정을 두 사람이 휴대폰으로 함께 보는 웹앱으로 만들고, 경비는 Postgres DB(Neon)에 실제 지출을 기록해 총액과 항목별 지출을 바로 확인하게 한다. 출발이 11/30이라 **11/27까지 배포**를 마감으로 둔다.

지금 일정은 HTML 페이지 하나(`docs/reference/honeymoon.html`)로 되어 있고, 체크 상태와 경비 수정값이 각자 브라우저에만 저장된다. 그래서 두 사람이 같은 상태를 볼 수 없고, 여행 중 실제 지출을 쌓아 둘 곳이 없다.

**성공 기준**

- 두 사람이 각자 휴대폰에서 같은 일정, 체크리스트, 경비를 본다.
- 지출 한 건을 10초 안에 기록한다(금액, 통화, 항목 3개 입력).
- 총 지출, 1인당 금액, 항목별·날짜별 지출을 한 화면에서 원화로 본다.
- 출발 전 체크리스트 완료율을 함께 추적한다.

## 사용자와 범위

사용자는 부부 두 사람뿐이다. 회원가입이나 다른 여행 생성은 만들지 않고, 이번 여행 하나만 다룬다. 주 사용 환경은 현지에서 쓰는 휴대폰 브라우저다.

## 데이터 모델

테이블은 10개이고, 경비는 `expense`(실제 지출)만 쓴다. `budget_item` 테이블과 `expense.budget_item_id`, `tax_free_*` 컬럼은 2026-11-08 예산·택스리펀드 기능을 뺀 뒤 쓰지 않는다(마이그레이션 없이 남겨 둠). 유로 지출은 기록할 때의 환율과 원화 금액을 함께 저장해서, 나중에 기본 환율을 바꿔도 이미 쓴 돈의 원화 금액은 변하지 않는다.

시간은 현지 시각으로 저장하고 날짜마다 시간대를 둔다. 포르투는 `Europe/Lisbon`(UTC+0), 바르셀로나는 `Europe/Madrid`(UTC+1)라 12/4 이동일에 1시간 차이가 생긴다. 다음 일정 계산은 이 시간대를 기준으로 한다.

스키마의 기준은 Drizzle 스키마(`src/shared/db/schema.ts`)다. 현지 날짜는 시간대 변환이 끼지 않도록 `'2026-11-30'` 같은 문자열로, 유로 금액은 센트 단위 정수(`amountMinor`)로 저장해 소수점 오차를 막는다. Postgres가 enum 값을 DB에서 강제하지만, 사용자에게 알맞은 오류를 보여주도록 입력값은 Zod로 먼저 검증한다.

**시드 데이터.** 지금 HTML 페이지 내용을 그대로 옮긴다. 여행 날짜 8행, 일정 항목 51개, 주의사항 3개, 체크리스트 6그룹 30개, 예약 7건이다(예산 항목 21개도 들어 있지만 화면에서 쓰지 않는다). 추출본은 `docs/seed-data.json`에 있다. 시드는 `src/shared/db/seed.ts` 하나로 만들고 여러 번 실행해도 같은 결과가 나오게 한다.

여권번호와 카드번호는 어느 테이블에도 저장하지 않는다.

## API와 서버 로직

읽기는 Server Component가 DB를 직접 조회하고, 쓰기는 모두 Server Action으로 처리한다. 별도 REST API는 CSV 내보내기 하나만 둔다. 모든 입력은 Zod로 검증하고, 쓰기 후에는 해당 경로를 `revalidatePath`로 갱신한다.

| 이름                               | 종류          | 하는 일                                          |
| ---------------------------------- | ------------- | ------------------------------------------------ |
| `login(passcode, userId)`          | Server Action | 비밀번호 확인 후 서명된 세션 쿠키 발급(30일)     |
| `toggleChecklistItem(id, checked)` | Server Action | `checked_by`, `checked_at` 기록 또는 비움        |
| `createExpense(input)`             | Server Action | 환율 스냅샷과 원화 금액을 계산해 저장            |
| `updateExpense(id, input)`         | Server Action | 수정. `amount_krw`를 직접 고치면 재계산하지 않음 |
| `deleteExpense(id)`                | Server Action | 삭제(화면에서 한 번 더 확인)                     |
| `updateSetting(key, value)`        | Server Action | 기본 환율 변경                                   |
| `updateItineraryItem(id, input)`   | Server Action | P1. 시간·메모·숨김 변경                          |
| `GET /api/expenses.csv`            | Route Handler | P1. 지출 내역 CSV(UTF-8 BOM, 엑셀 호환)          |

**경비 계산 규칙**

1. 유로 지출의 원화 금액 = 금액 × 저장 당시 환율, 원 단위 반올림. 카드 청구액이 나오면 원화 금액을 직접 고친다.
2. 총 지출 = 지출들의 원화 금액 합. 1인당 = 총 지출 ÷ 2(반올림).
3. 항목별·날짜별 지출 = 같은 항목·날짜의 원화 금액 합.

이 계산은 `src/entities/expense/model/budget.ts`의 `summarizeExpenses` 순수 함수에 모으고 단위 테스트를 붙인다.

## 기술 스택과 배포

Next.js(App Router)와 TypeScript로 만들어 Vercel에 배포하고, DB는 Neon(서버리스 Postgres)을 쓴다. 로컬 개발과 운영이 같은 Neon DB 하나를 쓴다.

```
휴대폰 브라우저 ──HTTPS──▶ Vercel · Next.js App Router
                           ├─ Middleware: 세션 쿠키 확인, 없으면 /login
                           ├─ Server Components: 화면 조회 ──읽기──▶ Neon (Postgres)
                           └─ Server Actions: 저장, Zod 검증 ──쓰기──▶ Neon (Postgres)
GitHub 푸시 ──배포──▶ Vercel (main = 운영, PR = 미리보기)
```

| 영역         | 선택                                                                        | 메모                                                                       |
| ------------ | --------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 프레임워크   | Next.js App Router, TypeScript strict                                       | 조회는 Server Components, 쓰기는 Server Actions                            |
| DB           | Neon Postgres                                                               | 로컬과 운영이 같은 DB                                                      |
| ORM          | Drizzle ORM + `@neondatabase/serverless`                                    | 스키마는 `src/shared/db/schema.ts`, drizzle-kit 설정은 `drizzle.config.ts` |
| 마이그레이션 | `drizzle-kit generate`로 SQL을 만들어 커밋하고 `drizzle-kit migrate`로 적용 | DB가 하나뿐이라 `drizzle-kit push`는 쓰지 않는다                           |
| 입력 검증    | Zod                                                                         | 폼과 Server Action이 같은 스키마를 쓴다                                    |
| 스타일       | Tailwind CSS                                                                | 지금 페이지의 색을 CSS 변수로 옮긴다                                       |
| 인증         | 공유 비밀번호 + 서명된 쿠키(`jose`)                                         | 사용자가 2명뿐이라 외부 인증 서비스는 쓰지 않는다                          |
| 테스트       | Vitest                                                                      | `src/entities/expense/model/budget.ts` 계산 검증                           |
| 배포         | Vercel                                                                      | main은 운영, PR은 미리보기                                                 |

**환경 변수**

| 이름                    | 용도                                                  |
| ----------------------- | ----------------------------------------------------- |
| `DATABASE_URL`          | 앱이 접속하는 Neon 주소(pooled, `-pooler` 호스트)     |
| `DATABASE_URL_UNPOOLED` | drizzle-kit이 마이그레이션에 쓰는 Neon 직접 연결 주소 |
| `APP_PASSCODE`          | 두 사람이 공유하는 로그인 비밀번호                    |
| `SESSION_SECRET`        | 세션 쿠키 서명 키(32바이트 이상 무작위 값)            |

**배포 순서**

1. GitHub 저장소를 만들고 Vercel 프로젝트에 연결한다.
2. Neon에서 유럽 리전에 프로젝트를 만든다.
3. Vercel에 환경 변수를 등록한다. 로컬 `.env.local`과 같은 DB를 가리킨다.
4. Vercel 함수 리전을 DB와 같은 유럽 지역으로 맞춘다.
5. `pnpm db:migrate`로 `drizzle/`의 마이그레이션을 적용하고, `pnpm db:seed`를 한 번 실행한다.
6. main에 푸시해 배포하고, 두 사람 휴대폰에서 로그인과 지출 기록을 확인한다.
